# Day 06 Mini Challenge

에이전트가 수행한 실험이다. 학생의 사전 예상·개념 이해·개인 판단을 대신 확인한 것은 아니다.
ROI 선택(마우스)과 실제 Ch.-B. 값 입력(육안 확인)은 이미지를 확대해 확인한 값으로 대체했다. 값은 아래 '확인 필요'를 참고한다.

## 검사 대상

Ch.-B. 제품 코드

## 사용한 데이터

새로운 제품 이미지 4장 (`samples/day06/mini_challenge/product/`)

## 바꾼 OCR 설정

SN 검사:
숫자만 (`0123456789`, `^[0-9]{13}$`)

Mini Challenge:
영문 대문자 + 숫자 + - (`A-Z0-9-`, `^[A-Z0-9-]+$`)

## 사용한 전처리

original (PSM 7, 4배 확대)

## 결과

4장 중 OCR 성공: 3장
4장 중 OCR 실패: 1장

| 파일 | 실제 값 | OCR 결과 | Format OK | Exact |
|---|---|---|---|---|
| 0185973818825_side.png | NA679903-8A | NA679903-8A | True | True |
| 0386316000696_side.png | TI776224-2D | TI776224-20 | True | False |
| 0635619134582_side.png | KW156489-8R | KW156489-8R | True | True |
| 0924467469402_side.png | ER935556-3V | ER935556-3V | True | True |

## 실패한 이미지가 있었다면

파일:
0386316000696_side.png

OCR 결과:
TI776224-20

실제 값:
TI776224-2D

다시 사용해 본 전처리:
gray, clahe (교재 55절). 참고로 otsu, clahe_otsu도 확인했다.

| 전처리 | OCR 결과 | Exact |
|---|---|---|
| original | TI776224-20 | False |
| gray | TI776224-20 | False |
| clahe | T1776224-20 | False |
| otsu | TIT6224-20 | False |
| clahe_otsu | T1775224-20 | False |

결과가 좋아졌는가?:
아니오. 어떤 전처리로도 마지막 글자 `D`를 `0`으로 읽는 문제가 해결되지 않았고, clahe는 `I`를 `1`로 읽어 오히려 나빠졌다.
이 이미지는 SN 이미지보다 초점이 흐려 `D`의 닫힌 곡선이 `0`과 구분되지 않는다. 전처리보다 촬영 선명도(초점)가 원인으로 보인다.
Whitelist가 `D`와 `0`을 모두 허용하므로 문자 종류 제한만으로는 막을 수 없다. 형식 검사(Regex)는 통과하지만 값이 틀리므로 Expected 값 비교가 필요하다.

## 확인한 점

SN에서 사용했던
ROI → OCR → 문자열 정리 → 형식 검사 → 실제 값 비교
과정을 다른 문자 코드에도 다시 적용할 수 있었다.
Format OK는 4장 모두 True였지만 Exact Match는 3장만 True였다. 형식이 맞는 것과 값이 맞는 것은 다르다.

## 확인 필요

- `TI776224-2D`의 마지막 글자와 두 번째 글자(`I`)는 흐린 이미지에서 에이전트가 읽은 값이다. 다른 3개 코드가 모두 `영문 2자 + 숫자 6자리 + - + 숫자 + 영문` 형식이라 마지막은 `D`로 판단했다.
- 실제 인쇄값을 정답으로 확정하려면 사람이 원본 이미지를 직접 확인한다.
